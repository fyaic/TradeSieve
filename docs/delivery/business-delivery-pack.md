# 业务交付包

**适用版本：** `0.1.0a5`
**适用范围：** 业务演示、流程评审、合成数据试接入和技术选型
**不适用范围：** 真实交易自动放行、法律意见、生产替代现有合规团队

## 1. 建议阅读顺序

1. 用 10–15 分钟浏览[图文演示 PDF](https://github.com/fyaic/TradeSieve/releases/download/v0.1.0-alpha.5/tradesieve-alpha-local-demo-guide-zh.pdf)；
2. 按 README 的“一键本地演示”启动合成 CRM；
3. 依次演示“名单候选”“两用物项阈值”“CHPL 补证”和“普通询价”场景；
4. CRM 团队阅读 [API 接入说明](../getting-started/official-screening-cli.md)；
5. Agent 团队阅读 [MCP 与 Agent 接入](../getting-started/mcp-agent.md)；
6. 部署和安全团队阅读[技术交接](technical-handoff.md)与[外部依赖](../operations/external-dependencies.md)。

## 2. 业务演示建议话术

TradeSieve 不替代业务系统，也不要求把监管数据写进 CRM。CRM 在关键节点提交交易方、货物和业务动作，TradeSieve 返回三类保守动作：暂停并复核、保持拦截并补件、继续监控。来源或系统不可用时同样保持拦截。

演示时应强调：

- 名单名称相同只是候选，需要核实身份，不是自动定罪；
- HS 或 CHPL 候选只提示增强尽调，不等同于正式归类、禁运或许可结论；
- 技术阈值只覆盖已明确发布和审核的首批规则，不代表完整 Annex I；
- `MONITOR` 只表示已实现检查没有产生更强动作，不是放行；
- 页面中的客户、金额、路线、单证和技术参数都是合成数据。

## 3. 验收场景

| 场景 | 预期业务效果 | 验收重点 |
| --- | --- | --- |
| 公开名单名称候选 | `RED / HOLD` | 暂停当前动作；显示来源版本和定位；等待人工核验身份 |
| `3A001.e.1` 技术阈值命中 | `RED / HOLD` | 显示逐项事实、单位、证据引用和来源绑定规则 |
| CHPL Tier 3A 候选 | `YELLOW / REQUEST_EVIDENCE` | 只要求增强尽调，不宣布受控或禁止 |
| 普通合成询价 | `MONITOR` 或补件 | 不出现自动放行文本 |
| 来源未刷新、陈旧或损坏 | 服务不可用并继续拦截 | 旧数据不静默冒充实时结果 |
| REST、CLI、MCP 同轮调用 | 相同 bundle 与业务动作 | 三种入口不各自维护规则；无效 MCP 请求被拒绝 |

这个内部交付检查评分衡量当前版本是否能够被业务团队领取、理解、演示和用合成数据试接入，不衡量生产运营或法律覆盖，也不是第三方认证。

## 5. 交付物清单

- GitHub Release：源码包、Python wheel/sdist、校验和、SBOM、构建证明与 PDF；
- README：首页快速入口、效果截图、使用方式、进度和边界；
- 合成 CRM：五条中国国际物流风格的固定询报价；
- 接口：认证 REST、CLI、本地只读 MCP；
- 证据：接口一致性、MCP 冒烟、Codex Agent 调用、官方来源联网验收；
- 文档：业务交付包、技术交接、外部依赖、发布安装、安全和架构决策。

## 6. 交付时不要做的事

- 不把真实客户数据复制进演示 fixture、截图、Issue、PR 或聊天工具；
- 不把本机 demo token 复制到共享或生产环境；
- 不把模拟 CRM 页面直接暴露到公网；
- 不把名单候选、CHPL 候选、未命中或 `MONITOR` 当成法律结论；
- 不删除或覆盖用于审计的来源、请求和结果引用。

## 7. 下一步需要业务团队确认

1. 哪些节点必须拦截：准入、报价、订单、订舱、装运、收付款；
2. 每个节点的最小必填字段和责任人；
3. `HOLD` 和 `REQUEST_EVIDENCE` 的响应时限、升级路径和替代人；
4. 允许进入内部经验池的材料类型、保留期和访问人群；
5. 试点只使用合成/脱敏数据，还是进入受控真实交易验证。
